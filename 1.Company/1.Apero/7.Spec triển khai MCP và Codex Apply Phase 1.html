Quyết định và căn cứ

“Codex Apply” trong tài liệu này là tool apply_patch của OpenAI Responses API. Không có endpoint tên codex apply. Tool trả thao tác tạo, sửa, xóa file. Ứng dụng gateway áp các thao tác đó vào worktree cách ly.

Chọn MCP khi

Nhân viên gọi công cụ Wandura hoặc gateway ngay trong Codex, Claude Code, hoặc client có MCP. Việc chính là tìm template, xem giá, tạo job ảnh/video/audio, hoặc hỏi route và usage.

MCP thuần không đổi model chính của Codex. Muốn Claude Code tự chuyển model thì phải có plugin Mod, từ Claude Code 2.1.287 trở lên.

Chọn Codex Apply khi

Cần một workflow trong gateway nhận yêu cầu sửa code, sinh diff, chạy lệnh kiểm tra đã cho phép, và chỉ tạo branch hoặc PR nháp sau khi người duyệt.

Nhân viên có thể bấm từ trang nội bộ hoặc gọi tool MCP. Cả hai cửa đều vào cùng worker. Không mở hai đường ghi repo.

Với 10 người, làm MCP trước nếu mục tiêu là đưa công cụ Wandura vào việc hằng ngày. Làm Apply khi đã chốt cần sản phẩm sửa repo. Bật cả hai thì cộng seat client còn thiếu và hạ tầng còn thiếu. Ngân sách OpenAI và ví Wandura chỉ lập một lần.

Số liệu lấy từ tài liệu cùng thư mục, đã đối chiếu đến 29/10/2026. Thứ tự chi phí của gateway Apero vẫn là: subscription từng người, rồi API có trần, rồi máy tự chạy. Phase 1 dừng ở hai bậc đầu.

Hướng A — MCP

Việc cần giao

Đưa thao tác có kiểm soát vào client nhân viên đang dùng. Có hai sản phẩm Wandura, không trộn ví:

  • MCP public: URL https://www.wandura.ai/api/mcp. User đăng nhập, trừ credit trên website. CLI @wandura/cli. MCP local @wandura/mcp. Tool server gửi về, hiện gồm các luồng search_templates → preview_generation → clone_template, hoặc preview_render → render_video / render_image / render_audio → get_generation.
  • API v2: server gọi server, API key và product wallet. Gói Basic và Growth trên website không được coi là tiền trả cho API v2. Muốn BFF gọi API v2 thì xin key và báo giá Enterprise.

Nếu chỉ cần nhân viên tạo ảnh, video, audio trong Codex: cài MCP public, không viết lại client trong gateway. Adapter tự viết chỉ khi gateway phải gắn policy, sổ usage và trần nội bộ lên trên Wandura.

Rule chọn model, lấy từ MCP.md: việc nhỏ, lọc log, tóm tắt dùng Haiku; viết code hằng ngày dùng Sonnet; debug khó hoặc thiết kế hệ thống dùng Opus. Haiku chỉ chạy một lần đầu phiên để chọn, nhận mô tả task và thông tin repo tối thiểu. Lỗi bộ chọn thì giữ model hiện tại hoặc hỏi người dùng. Không âm thầm chuyển sang provider khác.

Codex: MCP chỉ để gọi tool. Model Codex do cấu hình client chọn. Claude Code: muốn đổi model từng lượt thì Mod bắt turn.step, gọi POST /v1/route với tóm tắt ngắn, rồi gắn model đã chọn vào event. Giữ streaming và usage event.

Các bước làm, xong bước này mới sang bước sau

  1. Chốt cửa. Một trong ba: MCP public Wandura trong Codex; MCP local trỏ gateway nội bộ; hoặc Claude Code kèm Mod. Ghi danh sách 10 tài khoản. Mỗi người một login.
  2. Read-only trước. Bật gateway_list_models, gateway_route_preview, gateway_usage_summary hoặc tool đọc của MCP public. Chạy thử 10 user. User A không đọc được usage của user B.
  3. Preview giá. Một job media mẫu hiện giá và dừng. Chưa có nút xác nhận thì không phát sinh credit.
  4. Write có chốt. Bật create chỉ khi sổ, idempotency và thu hồi quyền đã chạy. Gửi cùng idempotency key hai lần thì một job.
  5. Mod, nếu cần chọn model. Pin phiên bản Claude Code. Ca lỗi route giữ model cũ. Ca D0 trong kế hoạch 29/10 vẫn ra Haiku. Không gửi cả repo để phân loại.
  6. Tuần đo. Bốn số: phí seat, credit Wandura đã trừ, số lần preview bị hủy, số lần create thành công. Đối chiếu dashboard Wandura.

Trang nội bộ đi cùng MCP

Nhân viên không mở được Codex vẫn dùng được việc qua trình duyệt. Browser chỉ gọi BFF. BFF giữ secret. Màn hình phase 1: đăng nhập SSO, tạo task, xem giá, danh sách trạng thái, duyệt trước khi trừ credit, admin xem usage. REST gợi ý: POST /v1/media/preview, POST /v1/media/jobs, GET /v1/media/jobs/{id}, GET /v1/usage. Cookie session có CSRF. File lớn đi bằng URL có chữ ký.

Hướng B — API Codex Apply

Việc cần giao

Thêm workflow sửa repo vào gateway. Phase 1 tạo diff và PR nháp. Không tự merge. Không tự deploy.

Thành phầnHợp đồng phase 1
Task APIPOST /v1/code/tasks tạo task. GET /v1/code/tasks/{id} đọc trạng thái. POST .../approve tạo branch hoặc PR nháp. POST .../cancel hủy.
WorkerMỗi task một worktree hoặc container, pin đúng base SHA. Không dùng chung cây làm việc. Context chỉ lấy file trong allowlist, hướng dẫn repo và lệnh build. Bỏ .env, credential, artifact, node_modules.
ModelPin gpt-5.5 vì tài liệu Apply Patch liệt kê model này. ID nằm trong cấu hình để đổi sau smoke test. Gửi tools: [{"type":"apply_patch"}].
Vòng sửaMỗi apply_patch_call được kiểm path, áp vào scratch, trả đúng một apply_patch_call_output theo call_id. Tiếp bằng previous_response_id. Tối đa 4 lượt.
HarnessChỉ create_file, update_file, delete_file. Từ chối path tuyệt đối, .., symlink ra ngoài, path ngoài allowlist, file quá lớn, binary, và file secret. Một operation hỏng thì cả lượt không ghi dở.
Kiểm traModel không có shell. Worker chạy formatter, linter, typecheck, test nằm trong allowlist, trong sandbox.
GitGitHub App quyền tối thiểu trên repo pilot. So SHA lúc tạo task với SHA lúc duyệt. Người duyệt diff rồi mới có branch. Phase 1 không push lên nhánh mặc định.

Dữ liệu tối thiểu

task_id, user_id, repo_id, base_sha, status, response_id, model_id, token, tiền ước tính, tiền chốt, hash diff, mốc thời gian, kết quả kiểm tra. Prompt đầy đủ và snapshot source chỉ giữ trong hạn công ty đã duyệt, rồi xóa.

Trần cứng nằm ở hai lớp. Trong app: mỗi user và mỗi task có trần riêng, giới hạn số file, số byte, số lượt. Trên OpenAI: một project, hard spend limit. Limit dashboard có thể vượt nhẹ vì thống kê trễ, nên app phải tự chặn trước khi gọi.

Các bước làm

  1. Project API. Một organization project tên riêng cho gateway. Một service account. Key vào secret store. Hard limit $100/tháng, cảnh báo 50%, 80%, 100%. Cảnh báo 80% thì ngừng nhận task mới.
  2. Harness không cần mạng. Bộ test từ chối ../, symlink, path ngoài allowlist, file secret. Operation lỗi trả failed và cây scratch giữ nguyên.
  3. Worker một job. Pin SHA, áp một patch mẫu, chạy một lệnh allowlist, ra diff. Concurrency phase 1 là 1 hoặc 2 job.
  4. Nối Responses API. Smoke một task thật trên repo pilot, model gpt-5.5, tối đa 4 lượt. Ghi token và tiền vào sổ.
  5. Cửa cho người. MCP dùng code_task_* hoặc trang nội bộ gọi cùng REST. Cả hai hiện diff trước khi approve. Approve tạo PR nháp. Cancel dừng job đang chạy.
  6. Mở dần. 2 đến 3 kỹ sư trước. Đủ tiêu chí nghiệm thu rồi mới đủ 10 người.

Không đưa vào phiếu mua

  • Máy 8×H100, thuê hoặc mua, ở Mỹ hay Việt Nam.
  • API key cá nhân cho 10 người khi đã có project key phía server.
  • Thêm model API chỉ để gọi MCP Wandura chính thức bằng credit website.
  • Ghế ChatGPT cho người chỉ dùng trang nội bộ.
  • 10 gói Growth hoặc một ví Enterprise cộng thêm 10 Basic cho cùng một người.
  • Compressor, fast mode, và Batch API trên đường Apply phase 1. Các mục đó thuộc kế hoạch tiết kiệm token, chưa gắn vào worker này.

Lộ trình và nghiệm thu

  1. Tuần 1 — Core. Map auth và database hiện có. Tạo sổ, trần từng user, audit. Tạo project OpenAI và đặt limit $100 dù Apply chưa nhận traffic. Chốt Wandura là credit cá nhân hay ví Enterprise.
  2. Tuần 2 — MCP, đủ 10 người, mới đọc và preview. Mỗi người một token. Thu hồi một user không làm chín người kia mất phiên. Mọi lệnh tốn tiền đều có giá, xác nhận và idempotency.
  3. Tuần 3 — Apply, 2 đến 3 kỹ sư. Patch không ghi ra ngoài worktree. Lỗi patch trả failed. Task có trần và nút hủy. Diff hiện trước PR. Không auto merge.
  4. Tuần 4 — Mở Apply tới 10 người nếu tuần 3 đạt. Trang nội bộ, nếu làm, login SSO, browser không thấy key, user chỉ thấy task của mình. Route lỗi không tự đổi provider. Mỗi route có model, lý do và route_id.

Nghiệm thu tiền: mỗi đô la API và mỗi credit Wandura gắn được với một user. Cảnh báo 50/80/100 đã cháy đúng ngưỡng trên project thử. Số trong sổ khớp dashboard OpenAI và dashboard Wandura ở mức làm tròn nhà cung cấp công bố.
